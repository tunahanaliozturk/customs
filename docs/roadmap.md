## Progress

- **M0**, 2026-11-22: done. Scaffold copied from waystation's shape, design, roadmap and five ADRs. The binary prints `customs 0.0.0`. `cargo fmt`, `cargo clippy` with warnings as errors, `cargo build` and `cargo test` pass locally on Windows; CI has since run on GitHub and is green.
- **M1**, 2026-11-22: done locally, not yet pushed. Built `graph`, `locate`, `archive`, `folder`, `inventory`, `report` and `cli`, with rules C101 to C105, C003 and the gaps C001 and C002, about 2,600 lines of code with 800 lines of unit tests and 760 of integration tests.
  - Exit tests, each seen failing before the code existed, when the binary still printed only its name: golden text and JSON for seven fixture scans (lock files v1 and v2, assets files v3 and v4, a packages folder, a `.nupkg`, a missing package); a `BUILD/` folder in capitals, in a folder and in an archive, is C101; a zip bomb (16 MiB of zeros in 16 KB) is a C002 gap with no byte read; an entry whose headers claim 64 bytes and hold 16 MiB is read to at most 64 bytes; an archive with 50,001 entries is a C002 gap before any entry is listed; `../`, `%2E%2E/`, rooted and drive-letter names are C003; a graph naming a package that is not on disk exits 3. The memory part of the exit test is asserted on the bytes read and entries listed, as counted by the scan, because `unsafe` is forbidden and a counting allocator needs it. Exit code precedence, case collisions, escaped ANSI and bidirectional text, skipped `Project` entries and links that are not followed have tests too.
  - Known-wrong variants, each tried by hand and each made a test fail; none failed to compile. Case-sensitive folder matching: exit test 2, five golden tests and two unit tests. ASCII-only case folding: the unit test with a dotless `ı` (that test pinned the wrong behaviour; see the review round below). No declared-ratio check: the zip bomb test. No entry count before parsing: the 50,001-entry test, as the `zip` crate then parsed every entry. No `..` check, and no `%XX` unescaping: the C003 test. Links followed, by reading the file type through the link: the link test, which ran on Windows here, as this machine lets a process create symbolic links without administrator rights. No case-collision check: the collision test. Gaps ranked above findings: the precedence tests. Bidirectional controls not escaped: the escaping tests. `Project` entries read as packages: the lock file tests. A missing package not reported: exit test 4. The 64-byte cap ignored: the golden JSON, through the bytes read. A first try at the link variant, dropping the link check, was not caught, because the link then fell through to "not a regular file" and was still not followed; it was not a variant that follows links.
  - On real data, read-only, on 2026-11-22: a whole local cache of 4,420 package versions scanned in 39 seconds on Windows, with one gap (a half-extracted folder) and no C003. 1,000 random `.nupkg` files from it compared with their extracted folders found one false C003: a published package names entries `analyzers/cs//A.dll`. Fixed by dropping empty segments, as NuGet does; after that, all 996 that could be named agree, and 4 tool packages whose file names are not `id.version.nupkg` were skipped. An assets file of 210 packages scanned in 2.7 seconds.
  - Review round, 2026-11-22. An independent review ran the binary and found defects, all fixed test first:
    - The entry-count check could be bypassed. With junk in front, a classic end record that declares one entry, and a zip64 record away from where its locator points, customs counted one entry while the `zip` crate searched, found the zip64 record and parsed 2,000,000 entries in 424 MB. customs now accepts only the canonical layout described under Limits in the design, refuses anything else as C003 without opening it, and limits the central directory to 64 MiB. All 4,444 `.nupkg` files of the local cache were scanned again: none was refused by the layout rule. 4,288 signed and 132 unsigned packages passed, 24 were skipped because their file names are not `id.version.nupkg`, and 1 is not a zip at all (a C001 gap; Python's zip reader refuses it too). Archive and folder gave the same inventory for all 4,420. Six published packages hold `packageIcon.png` twice and get the C003 for duplicate names, as before the review.
    - A package's ID or version folder that is a link was followed through a graph and dropped silently with `--packages-dir`. It is now C003 and a C001 gap, never read. An ID folder that is a link under `--packages-dir` alone is a C001 gap of the input, because without a version there is no package to put the C003 on.
    - Backslashes in entry names were turned into `/` before `%XX` was decoded, so `..%5Cx` passed. The order is now the design's. Names with a control character, and names whose bytes are not UTF-8, are C003.
    - Text from graph files reached stderr raw. Usage errors are now escaped like the report.
    - The folder comparison folded case wider than .NET: `buıld/` was taken for `build/`, which NuGet does not do. Folder names now compare as ASCII case-insensitive; the old unit test and the ASCII-only variant above had pinned the wrong behaviour. IDs are lowercased character by character, as `ToLowerInvariant` does.
    - Smaller: folders now count against the entry limit as they are listed (120,000 empty folders had been walked for 22 seconds and reported complete); one unreadable folder under `--packages-dir` is a gap, not exit 2; a version part over 2,147,483,647 is not a version; the ratio read is written as the design says; the test with a lying header now declares 200 bytes, not the 64 of the cap, and asserts a clean read of exactly 64; the link tests fall back to a junction on Windows and fail if they can make neither.
    - Variants tried again, each caught: the zip64 record not required to end at its locator (the decoy-record test); the directory not required to end at its end record (the test with an overstated directory size; the first try was not caught, because the header check at the directory start and the 64 MiB limit also stopped the archives built so far); backslashes turned into slashes before unescaping; control characters allowed; package folder links followed; folder children not counted; Unicode folding for folder names; the declared size trusted for the read length (not caught until the lying-header test asserted a clean read); graph text printed raw on stderr. The reviewer could not make a symbolic link from PowerShell without administrator rights. Rust's `symlink_dir`, which the tests use, asks Windows for an unprivileged link, and that works on this machine: the link tests ran here before the junction fallback existed, which is why the link variant was caught.
  - Not seen here: the tests on Linux and macOS, the MSRV job on Rust 1.89 and `cargo deny`. They run in CI after the push. Open questions 4, 9 (`zip`) and 12 are settled in the design.

## Order of work inside a milestone

1. Write the exit test first, and see it fail.
2. Implement until it passes.
3. Try the milestone's known-wrong variants by hand, see a test fail for each, and record the result above.
4. Run the benign corpus if the milestone touched a rule.
5. Record any decision that is hard to reverse as an ADR, and settle the milestone's open questions in the design.
